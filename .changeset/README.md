# Changesets

Hello and welcome! This folder has been automatically generated by
`@changesets/cli`, a build tool that works with multi-package
repos, or single-package repos to help you version and publish your code.
You can find the full documentation for it [in our repository](https://github.com/changesets/changesets)

We have a quick list of common questions to get you started engaging with this
tool.

## I am in a multi-package repository. Should I use multiple changesets?

Yes, use one changeset per logical change (regardless of how many packages
that change affects).

## What does this mean for me as an end user?

If you're an end user and you're just adding stuff to your project, you can
ignore this whole folder! It's designed to be used in tandem with tools
that pull the version out of `package.json`, and generate changelogs
and publish based on the presence of these files.

## What issue does this resolve?

When collaborating on packages, versioning, and changelogs can become a
bit tricky. This tool aims to solve this problem by encouraging you to
keep a "changeset" for every logical change to your packages. A changeset
holds two key pieces of information: a version type (following [semver](https://semver.org/))
and change information to record in a changelog.

By adding a changeset to every logical change, you build up a changelog and
set of version bumps for that change, which specify how a group of changes
should be released.
